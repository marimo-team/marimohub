# MarimoHub docs

Self-hostable, provider-agnostic platform for storing and running
[marimo](https://marimo.io) notebooks. No separate database — everything lives in
an object store, and you choose your own storage, compute, and identity providers.

## Start here

- [Getting started](./getting-started.md) — choose your storage, compute, and
  auth, then deploy.
- [Deployment options](./deployment-options.md) — config-driven (env vars) vs.
  SDK/library composition.
- [Testing locally](./testing-locally.md) — run the whole stack on your laptop
  with no external services.

## The three backends

Every deployment picks one option per part:

- [Auth](./auth.md) — who can sign in (`oidc`, `cloudflare-access`, `dev`), plus
  the [authorization roles](./auth.md#authorization-roles) (`viewer` / `editor` /
  `admin`) that gate what they can do.
- [Storage](./storage.md) — where notebooks live (`s3`, `gcs`, `r2`, `memory`).
- [Compute](./compute.md) — where kernels run (`coreweave`, `modal`, `kubernetes`,
  `docker`, `e2b`, `local`, `cloudflare`, `none`), plus the
  [sandbox image](./sandbox-image.md) (bring your own container) each kernel runs in.

## Capabilities

- [Managed AI](./ai.md) — give every notebook a working AI assistant with no
  user-supplied key; the hub holds the provider key and proxies requests.
- [Syncing from external sources](./syncing.md) — serve read-only notebooks whose
  source of truth is pushed in from a git repo or CI.
