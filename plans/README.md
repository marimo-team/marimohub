Two extra commits were made during landing, outside the original plans:

- **Format normalization** (`vp fmt`): the repo did not pass its own formatter
  (110 files). Normalized first so `pnpm check` is a usable gate and CI (plan 001) is green.
- **Monotonic version ids**: plan 008's version-pruning test was an intermittent
  flake because `createVersionId()` used a non-monotonic ULID; same-millisecond
  saves didn't sort by creation order. Fixed at the root by making version ids
  monotonic (like event ids already were) — pruning is now deterministic.

Result: baseline was 132 tests; **202 tests** now pass (`check + test + build`
all green, no flakes over repeated runs).

## Adaptations made during landing (the repo moved after the plans were written)

- **Base moved**: the plans were written against `0565ec6`; landing happened on
  top of `9eb6c63` ("Migrate web UI to Tailwind v4 + shadcn"). Plans 009/011/012
  were reconciled against the Tailwind-migrated web; 012 additionally corrected
  the docs' frontend-stack description.
- **Plan 005 chose policy A** (remove the unauthenticated `/api/sandbox/*`
  routes) — grep confirmed no SPA/example caller; the SPA provisions kernels via
  the session routes.
- **Plan 009 chose the conformance-test approach** (not derivation): deriving the
  API response schemas from core would have changed the published OpenAPI doc
  (the API copies intentionally differ — `schema_version` enum, datetime format,
  id patterns). The runtime contract is byte-identical (SHA-verified); a
  conformance test now fails on drift.

## Findings considered and rejected during the audit (so they aren't re-audited)

- OIDC "missing `algorithms`" (SEC-03): jose + JWKS is already safe against
  `none`/alg-confusion; defense-in-depth only.
- Sandbox `exec` "injection" (SEC-05): by design (sandbox runs the user's code);
  the real gap (any user → any sandbox id) was handled as authorization in 005.
- Open reads (SEC-02): documented v1 scope cut, listed under Direction.
- Modal request signing / rate limiting (SEC-09): speculative, external.
- Heartbeat "stale coalescing" (PERF-06): the coalescing logic is correct. (The
  separate real bug — heartbeat reviving terminal sessions — was fixed in 006.)
- `deleteProject` getProject race (CORRECTNESS-03): benign under the CAS retry.
- `.editorconfig` (DX-05) / "staged hooks are dead code" (DX-06): low value; the
  staged hook is wired by vite-plus via `vp config` on `prepare`.
- AWS SDK / workers-types minor lag (MIGRATION-03/04): routine hygiene.
- Per-request `assertProjectRole` / snapshot-rewrite cost (PERF-03/04/08): real
  trade-offs correctly chosen for the documented 10×100 scale target.
